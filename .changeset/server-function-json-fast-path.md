Server function results negotiate the JSON fast path and the codec loads lazily. The server's `encodeResult` now mirrors the client's argument negotiation: JSON-safe results (single-flight `{ value, data }` envelopes included — a void mutation's envelope omits the `value` key so it qualifies) ride `BodyFormat.Json` as plain `JSON.stringify`, void results send no body at all, and only values needing typed reconstruction — Dates, Maps, streams, promises, thrown Errors — keep the Serialized streaming path. On the client, the seroval codec is no longer a static import of the shared wire layer: `serializeStream`/`deserializeStream` dynamically import `../serializer.js` the moment a Serialized body actually has to be encoded or decoded, so a plain-data app's eager graph carries only the transport (~2.9 kB gz measured, down from ~7.3) and the codec arrives as a lazily-fetched chunk only when a rich value appears on the wire. Negotiated per response — mixed pages simply carry both formats, no compat flag. `isJSONSafe` moves to the shared layer (exported) since both peers now negotiate with it; the size guard grows a `server-functions client: eager transport` scenario (2654 gz ceiling, seroval forbidden) and models the consumer-side codec split via `lazyCodecSplit`.
