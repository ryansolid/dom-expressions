`isJSONSafe` survives cyclic and deeply nested values, so negotiation failures stop masquerading as function errors (#566). Since the JSON fast path, the guard recursed with no cycle detection: a server function returning a cyclic structure threw `RangeError: Maximum call stack size exceeded` during RESULT ENCODING — after the function had run and its side effects committed — and dispatch's catch reported it as the function itself throwing (in production, a generic `Internal Server Error` over a call that succeeded). The guard now walks an explicit stack with an ancestor set and a depth ceiling: cycles answer "not JSON-safe" and fall to the seroval codec, which round-trips them — restoring the pre-fast-path behavior for these values on results, single-flight envelopes, and (the pre-existing client-side variant) argument lists, where a cyclic argument now reaches the `serializeArguments` fallback instead of rejecting before it (with `enableRichArguments()` it rides the codec; without, the caller gets the actionable guidance error, not a RangeError). Deep acyclic nesting `JSON.stringify` handles fine (~8k levels used to overflow the guard's heavier frames) stays on the JSON fast path — it must, since the codec's depth limit protects the decoding peer and cannot carry it. Cycle detection is ancestor-based on purpose: a value referenced twice without a cycle is still JSON-safe (stringify duplicates it, as the fast path always has), so aliased plain data keeps the codec out of the bundle. Belt and braces on both peers: the server's `encodeResult` JSON attempt and the client's argument fast path are wrapped so anything negotiation can still hit (a throwing getter, an engine limit) falls through to the codec instead of escaping as a phantom call failure. The eager-transport size scenario re-guards at actual+20 (2729 gz measured, +95 for the guard rewrite and the argument-leg fallthrough).
